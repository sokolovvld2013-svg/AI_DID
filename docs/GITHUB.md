# Публикация на GitHub

Репозиторий уже инициализирован: 92 коммита, ветка `main`, remote `origin`
уже настроен. Ниже — что проверять перед каждой выкладкой и что делать, если
в историю попало лишнее.

## Перед push

1. **Не коммитьте `.env`** — в нём ключи API. В репозитории только `.env.example`.
   Сверьтесь с `.gitignore`: он закрывает `.env`, `.env.*`, `users.json`,
   `app_settings.json`, каталоги загрузок и кэшей.
2. Посмотрите, что вообще пойдёт в индекс, ничего не применяя:

   ```bash
   git add -An          # перечисляет кандидатов
   git status --short   # плюс уже отслеживаемые изменения
   ```

   В списке не должно быть `.env`, `users.json`, `chroma_data/`, `venv*/`,
   `models/`, `*/uploaded/`, `*.log`.
3. Локально настройте окружение: `cp .env.example .env` и заполните секреты.
4. `logo.png` и `favicon.png` кладите в `static/img/` или добавляйте в
   `.gitignore`, если публиковать их не хотите.

## Учётные записи отдельно от репозитория

`users.json` содержит Argon2id-хеши паролей и `session_secret` для подписи
сессий, поэтому он не версионируется. На сервере первый администратор создаётся
командой (пароль спросит в терминале):

```bash
python -m scripts.manage_users add admin --admin
```

Дальше учётки заводятся из веб-интерфейса: Настройки → Управление пользователями.

## Если ключи всё-таки попали в историю

Немедленно перевыпустите ключи в кабинетах DeepSeek и GigaChat, затем уберите
секрет из истории и перепишите её:

```bash
pip install git-filter-repo
git filter-repo --path .env --invert-paths
git push --force --mirror origin
```

Важно: после этого все хеши коммитов меняются, поэтому с клонами нужно
перебазироваться, а старые PR перестают работать. Если секрет утёк, вычистка
истории его не отменяет — пароль всё равно надо менять.

## Известная особенность этой истории

В репозиторий однажды попало виртуальное окружение `venv311/`: 114 МБ чужих
DLL, самый большой блоб — 56 МБ. Оно удалено из рабочей копии и закрыто в
`.gitignore`, но осталось в истории, то есть уже на GitHub. Записи по этому
поводу 114 МБ, но отдельный файл больше 100 МБ (жёсткий предел GitHub) там
нет, поэтому push проходит.

Варианты, если захотите вычистить:

- `git filter-repo --path venv311 --invert-paths` — история сохраняется, но
  переписывается целиком, нужен `--force` push и перебазирование клонов;
- начать репозиторий заново одним коммитом, если история не нужна.

Самостоятельно историю не переписывал — операция необратимая. Решайте сами.

## Клонирование на сервере

```bash
git clone https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПО.git
cd ВАШ_РЕПО
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# отредактировать .env
python -m scripts.manage_users add admin --admin
uvicorn main:app --host 127.0.0.1 --port 8000
```

Подробности установки и systemd-юнитов — в разделе «Развёртывание на сервере»
в [README.md](../README.md), он же лежит в `deploy/install.sh`.
