# Парсер Картотеки арбитражных дел (kad.arbitr.ru)

Папка содержит **локального агента** парсера КАД. Агент запускается на компьютере
сотрудника, получает задания из приложения «Юрист», открывает видимый браузер,
обходит КАД и отправляет на сервер записи и готовый Excel-файл.

Очередь, веб-интерфейс и хранение результатов находятся в основном проекте
«Юрист». В этой папке нет отдельного сервера и нет Streamlit-интерфейса.

## Быстрая установка на новый компьютер Windows

Для работы агента сотруднику не нужно устанавливать сервер, Streamlit или
`uvicorn`. Нужен только Python, папка этого проекта и обычный Chrome/Edge.

### Шаг 1. Установить Python

Установите Python 3.11 или новее с официального сайта:

<https://www.python.org/downloads/windows/>

Во время установки включите флажок **Add Python to PATH**. Проверка:

```bat
python --version
```

### Шаг 2. Получить проект

Скопируйте папку `lawyer\kad_scraper_local` на компьютер сотрудника, например:

```text
C:\kad-parser\lawyer\kad_scraper_local
```

Или скачайте репозиторий через Git:

```bat
git clone <адрес репозитория> C:\kad-parser
cd /d C:\kad-parser\lawyer\kad_scraper_local
```

### Шаг 3. Запустить установку агента

Откройте обычную командную строку **от имени текущего пользователя** и выполните:

```bat
cd /d C:\kad-parser\lawyer\kad_scraper_local
setup.cmd
```

Права администратора обычно не нужны. Запускать агента от имени `SYSTEM` или
как службу нельзя: браузер должен открываться в видимой пользовательской
сессии, чтобы сотрудник мог решить captcha.

`setup.cmd` автоматически:

1. создаст `.venv`;
2. установит зависимости из `requirements-agent.txt`;
3. попробует установить Chromium Playwright;
4. создаст `agent.env` из `agent.env.example`;
5. откроет `agent.env` для заполнения;
6. зарегистрирует запуск агента в Планировщике заданий Windows при входе пользователя.

Если Chromium Playwright не скачался, агент попробует использовать установленный
Google Chrome или Microsoft Edge.

### Шаг 4. Заполнить `agent.env`

В файл `C:\kad-parser\lawyer\kad_scraper_local\agent.env` внесите параметры:

```env
KAD_AGENT_SERVER=https://адрес-сервера
KAD_AGENT_TOKEN=пароль-этой-машины
KAD_AGENT_NAME=ivan-pc
KAD_AGENT_OWNER=логин-сотрудника
KAD_AGENT_LOG=logs\agent.log
```

Значения должны соответствовать серверному `.env`:

```env
KAD_AGENT_ENABLED=true
KAD_AGENT_TOKENS=ivan-pc:пароль-этой-машины
```

Для нескольких компьютеров добавляется отдельная пара `имя:пароль`:

```env
KAD_AGENT_TOKENS=ivan-pc:пароль1,petr-pc:пароль2
```

Токен должен содержать только латинские символы, цифры и ASCII-знаки. Не
используйте кириллицу: токен передаётся в HTTP-заголовке.

`KAD_AGENT_OWNER` — логин сотрудника. Если он указан, задания этого сотрудника
сначала предлагаются его компьютеру. Если машина занята или недоступна, задание
может взять другой свободный агент.

### Шаг 5. Проверить запуск вручную

После сохранения `agent.env` выполните:

```bat
cd /d C:\kad-parser\lawyer\kad_scraper_local
run_agent.cmd
```

В рабочем режиме консольный запуск можно оставить открытым для диагностики.
Агент должен вывести сообщение о подключении к серверу и ждать задания.

При запуске через Планировщик консоль не показывается, журнал находится здесь:

```text
C:\kad-parser\lawyer\kad_scraper_local\logs\agent.log
```

### Шаг 6. Проверить в приложении

Откройте «Юрист» → «Арбитражные дела (ИНН)». В блоке **«Состояние сбора»**
компьютер должен отображаться как подключённый и свободный.

Если написано «Агент пока не подключён»:

1. проверьте `KAD_AGENT_SERVER`;
2. проверьте совпадение `KAD_AGENT_TOKEN` и `KAD_AGENT_TOKENS`;
3. проверьте, что `KAD_AGENT_NAME` совпадает с именем до двоеточия на сервере;
4. откройте `logs\agent.log`;
5. убедитесь, что компьютер не спит и пользователь не вышел из Windows.

### Автоматический запуск после установки

После `setup.cmd` агент запускается автоматически при следующем входе в Windows.
Чтобы проверить без выхода из системы, запустите `run_agent.cmd` вручную.

Каждый новый сбор после этого запускается так:

1. войти в приложение «Юрист»;
2. открыть «Арбитражные дела (ИНН)»;
3. ввести ИНН;
4. при необходимости включить подробное обогащение и указать лимит;
5. нажать «Найти арбитражные дела»;
6. решить captcha в открывшемся браузере, если она появится;
7. дождаться готового результата и скачать XLSX.

## Ручная диагностика без очереди

Обычно агент запускается через `run_agent.cmd` и ждёт задания. Для проверки
одного локального сбора можно использовать:

```bat
cd /d C:\kad-parser\lawyer\kad_scraper_local
.venv\Scripts\python.exe -m kad_scraper --inn 5032034971 --limit 50 --enrich
```

Результат и чекпойнты будут записаны в локальную папку `output/`.

## Использование без интерфейса

```bash
python -m kad_scraper --inn 5032034971 --all
python -m kad_scraper --inn 5032034971 --limit 50 --enrich
```

Из кода:

```python
from kad_scraper import KadScraper, records_to_excel

result = KadScraper("5032034971", limit=50).run()

print(len(result.records), result.stop_reason)
for warning in result.warnings:
    print("-", warning)

open("kad.xlsx", "wb").write(records_to_excel(result.records, inn="5032034971"))
```

## Что собирается

Таблица результатов КАД содержит только четыре колонки: номер дела,
судья/суд, истцы и ответчики. Остальные поля есть только на странице карточки
(`/Card/<guid>`), поэтому они заполняются **только в режиме глубокого
обогащения** (галочка в интерфейсе).

| Колонка | Источник |
| --- | --- |
| Источник информации | константа `https://kad.arbitr.ru/` |
| Ссылка на источник | ссылка на карточку дела |
| Номер дела | таблица результатов |
| Истцы / Ответчики | таблица результатов, уточняется карточкой |
| Третьи лица / Иные лица | **только карточка**, раздел «Участники» |
| Статус | **только карточка**, вкладка «Карточки»: номер дела и суд последней инстанции + текст её судебного акта. Если акт ещё не вынесен, а дело уже ушло в вышестоящую инстанцию, добавляется «Рассматривается в апелляционной инстанции: <номер> <суд>». Если по делу назначено заседание, добавляется строка КАД «Следующее заседание: …» (дата, время, зал) — она может относиться к другой инстанции, чем акт. Ячейка кликабельная — открывает документ |
| Дата регистрации, Категория дела, Судья, Суд | таблица результатов |
| ИНН истцов / ИНН ответчиков / Участники (адреса) | таблица результатов |
| Страница КАД | служебная, для контроля полноты обхода |

## Как это работает

- Браузер запускается в **видимом** режиме (`headless=False`) с реалистичным
  Chrome User-Agent и набором stealth-настроек: КАД отсеивает headless заметно
  чаще.
- Ввод ИНН делается посимвольно с человеческими интервалами, а не через
  `fill()`, чтобы сработала штатная автодополнение КАД.
- Обход страниц: 25 строк на страницу, пауза 5–10 с между страницами, лимит
  500 страниц как предохранитель.
- Конец выборки определяется по исчезновению ссылки «Вперёд»
  (`#b-footer-pages li.rarr a`) и по совпадению текущей страницы с общим
  числом страниц. Дедупликация — по ссылке на карточку.
- После каждой страницы состояние сбрасывается в `output/`: JSON с полными
  записями (из него возобновляется сбор) и CSV для просмотра глазами.

## Что делать, если КАД не отдаёт результаты

КАД ограничивает частоту автоматических запросов. Приложение распознаёт обе
формы ограничения и честно об этом сообщает:

| Сообщение | Что произошло |
| --- | --- |
| Страница «Доступ заблокирован» | IP заблокирован (HTTP 429). Парсер ждёт остывания и пробует продолжить. |
| `stop_reason: throttled` | Главная открывается, а фоновый запрос (например `Kad/SearchInstances`) получает 429. |
| `stop_reason: captcha` | Показана PravoCaptcha — её нужно решить вручную в окне браузера. |
| `stop_reason: timeout` | КАД не ответил за отведённое время. |

Это ограничение на частоту запросов, а не на сам ИНН: если по контрагенту дела
есть, они появятся после паузы.

Рекомендации, если ограничения срабатывают:

- не запускать несколько сборов подряд, особенно с режимом обогащения;
- не включать `Глубокое обогащение` без необходимости — оно открывает по
  отдельному HTTP-запросу на каждое дело;
- оставить паузы 5–10 с как есть;
- после срабатывания ограничения подождать 15–30 минут.

## Что видно в таблице, а что — только в карточке

Таблица результатов КАД содержит всего четыре колонки: номер дела, суд,
истцы и ответчики. Поэтому без обогащения часть колонок выгрузки всегда пустая,
а в некоторых делах организации вообще нет в списке.

Типовой случай: КАД находит дело по ИНН, но организация участвует в нём
**третьим лицом**, а третьих лиц таблица не показывает. Такие дела легко принять
за «чужие». После обогащения карточки организация появляется в колонке
«Третьи лица» или «Иные лица».

Чтобы догрузить такие дела точечно, не пересобирая всю выгрузку:

```python
from kad_scraper import CheckpointStore, KadScraper

checkpoint = CheckpointStore("output", inn)
records, meta = checkpoint.load()

# дела, где искомого ИНН нет среди истцов и ответчиков
target = [
    record
    for record in records
    if not any(p["inn"] == inn for p in record.plaintiffs + record.respondents)
]

done, warnings = KadScraper(inn).enrich_records(target)
checkpoint.save(records, meta)
```

`enrich_records()` открывает только переданные карточки и не повторяет поиск.
Уже обогащённые записи пропускаются; чтобы обновить их, передайте
`skip_enriched=False`.

Важно: на карточке КАД показывает ИНН далеко не всегда, поэтому после
обогащения третьих лиц надёжнее сверять по **названию организации**, а не по ИНН.

# Архитектура работы

Вариант для команды: сбор запускается **кнопкой в браузере** на сервере, а
выполняется на компьютере, где установлен агент.

Почему нельзя просто обходить КАД на сервере: обход держится на видимом
браузере, домашней сети и живой сессии. На VPS это даёт captcha и 429, а
надёжного решения капчи автоматически нет. Поэтому обход остаётся у человека,
а сервер занимается очередью, историей и хранением.

## Схема работы

```
браузер сотрудника ──► сервер: «Начать парсинг»
                          │
                          └─ задание ──► агент на его компьютере (по открытому соединению)
                                            │
                                            └─ видимый Chrome, обход КАД
                                                  │
                          сервер ◄─ записи + Excel
```

Обратный канал не нужен: компьютер сотрудника за NAT, сервер не может
дозвониться до него. Поэтому агент **сам держит соединение открытым и ждёт в
нём** задание. Нажали кнопку — задание приходит по этому же соединению
сразу, без задержки на опрос.

Пока идёт обход, агент раз в 30 секунд шлёт пульс: компьютер может быть
занят обходом минутами, и без пульса сервер решил бы, что машина умерла, и
отдал задание другому.

## Серверная часть

Отдельного сервера в этом репозитории больше нет. Очередь, маршруты для агента
и вкладка «Арбитражные дела» живут в приложении «Юрист» — см. `lawyer/arbitr`
в его репозитории.

Агент ходит на этот сервер, поэтому адрес и пароль задаются в его `.env`:

| Переменная (в приложении «Юрист») | Назначение |
|---|---|
| `KAD_AGENT_ENABLED` | `true` — включить вкладку и маршруты агента |
| `KAD_AGENT_TOKENS` | пароли машин: `имя-машины:пароль,имя-машины:пароль` |
| `KAD_AGENT_HOLD` | сколько секунд агент ждёт задание в одном запросе, 30 |
| `KAD_ARBITR_QUEUE_TTL_HOURS` | сколько ждать машину, если её нет, 24 |
| `KAD_ARBITR_RETENTION_DAYS` | через сколько дней автоудаление, 10 |

Сервер обязательно ставьте за HTTPS-прокси: пароль идёт открытым текстом.

## 3. Использование

Сотрудник открывает панель в браузере с любого устройства, вводит ИНН и жмёт
«Найти арбитражные дела». На компьютере с агентом сам открывается браузер, сотрудник
решает капчу, если она появилась, и по закрытию браузера результат появляется
на сервере.

Если агентов несколько, задание достанется любому свободному — очередь
раздаётся сама. Кто именно выполняет, видно в списке заданий.

## Что происходит при сбоях

- **Агент выключился посреди обхода.** Сервер видит, что пульса нет дольше
  трёх минут, и возвращает задание в очередь — его возьмёт другой агент.
- **Сервер перезапустился.** Незакрытые задания возвращаются в очередь при
  старте, собранное ранее лежит на диске.
- **Сбор остановила капча или 429.** Собранное сохранено, задание помечено
  как «остановлено капчей» и его можно повторить позже. Код возврата при этом
  ноль: неполнота из-за КАД — это результат, а не сбой программы.
- **Машина в спящем режиме или за блокировкой экрана.** Видимый браузер не
  покажется, капчу решить нечем. Агент на такой машине задачи лучше не держать.

## Программный доступ

Очередью управляют через вкладку «Арбитражные дела» или её маршруты
(вход — сессия пользователя, пароль агента тут не работает):

```bash
# поставить задание
curl -X POST "https://сервер/lawyer/arbitr/jobs" \
     -H "Content-Type: application/json" -b "session=..." \
     -d '{"inn": "5032034971", "enrich": true}'

# сводка: задания и машины
curl "https://сервер/lawyer/arbitr/status" -b "session=..."

# записи задания постранично
curl "https://сервер/lawyer/arbitr/jobs/ID/records?offset=0" -b "session=..."

# выгрузка Excel
curl "https://сервер/lawyer/arbitr/jobs/ID/download" -b "session=..." -o выгрузка.xlsx
```

Excel собирает агент на компьютере сотрудника и присылает готовым файлом, поэтому
на сервере нет ни pandas, ни openpyxl.

```bat
.venv\Scripts\python.exe test_agent.py
```

Сквозная проверка протокола (очередь, выдача, приём отчёта, Excel, права) живёт
